# 长文流水线写作方法（通用报告域 · long-form-writing）

> 适用于受理「长文写作任务书」的写作类 agent（如 writer-agent），通用报告域（调研/分析/深度报告等非年报域）。
> 本文件是通用报告长文写作方法与流程的唯一事实源；编排器（确定性流水线）不下发写作要求，只注入任务数据。
> 输出协议与 annual-report 域完全一致（服务端同一解析器）。

## 1. 职责定位

- **agent 负责的事**：任务分解、章节成稿、反思优化——按本方法自主完成，不等待逐步指令。
- **编排器负责的事**：组装任务书（纯数据：节清单/指标表（可能为空）/引用清单/快照页原文）、解析输出、运行确定性核验、回灌违规清单。
- **框架提供的事**：技能加载（上下文）、会话记忆（同 session 多轮可见此前任务书与成稿）、任务规划工具（todo）。

## 2. 执行流程

1. **加载上下文**：先经 skill_tool 加载 `general-report` 技能与本文件；引用格式沿用 [C-n] 协议（见 `skills/annual-report/references/citation-style.md`，两域共用）。
2. **解读任务书**：任务书含任务目标（报告主题）、章节清单（`[S-n]` + 标题 + 分析洞察责任 + 关联引用）、指标数据表（通用域可能缺失，缺失时以资料原文为准）、引用清单、快照页原文、输出协议。
3. **自主分解**：按章节清单把任务分解为逐节写作计划（可使用框架 todo 工具记录与勾销）；识别各节的数据侧重与节间分工，避免重复堆砌同一材料。
4. **逐节成稿**：按「分节成稿法」（§3）写作每一节；口径与句式遵循 §4；引用标注遵循 §5。
5. **按输出协议输出**：任务书的输出协议是服务端解析契约，必须严格遵循：
   - 只输出章节清单所列各节的正文，不输出任务书解读、开场白或收尾总结；
   - 每节一个块，块首行只写 `[S-n]`（如 `[G-4]`），正文从下一行开始；`[S-n]` 与 `[C-n]` 方括号内不加空格（写 `[G-4]`，不写 `[ G-4 ]`）；
   - 最终答复是交付通道：本轮全部成稿块必须在最终答复中完整给出，中间轮次的构思、草稿与 todo 记录不算交付；最终答复首尾不附加任何总结、说明或工具使用情况；
   - 数据与事实陈述标注对应引用编号 `[C-n]`；派生结论标注「基于 [C-k] 计算」并给出依据；
   - 不编造快照页原文之外的数据。
6. **续写与修订响应**（见 §6、§7）：编排器可能发来续写指令或违规反馈，在同一会话内按协议响应。

## 3. 分节成稿法

- **篇幅**：每节正文 600-1200 字；宁短勿凑，不为凑字数重复材料。
- **结构**：总-分-收，中段至少两个自然段。首段给出本节核心判断（主体、什么事实、什么方向）；中段展开资料论证（每论断一条引用，逐项拆解背景、事实、结构、动因）；末段收口（趋势或关注点），不空喊口号。
- **数据侧重**：以任务书「分析洞察责任」为侧重参考，但允许跨节关联论证；同一材料全篇至多展开一次，其余位置仅引用结论。
- **语言**：简体中文；书面报告体；不用第一人称；不用夸张修饰词（"暴涨""暴雷"）；数值与百分比按引用清单/资料原文。

## 4. 口径与句式规范（与确定性核验器协作的表述纪律）

- **值与单位照抄**：任务书指标表（如有）中的值与单位一字不改（含千分位、%）；不得自行换算单位或四舍五入。
- **变动句式（重要）**：表述变动一律用「同比变动 -XX%」「较基期变动 -XX%」「增减 XX 个百分点」这类中性句式；**禁用「同比增长 X% / 同比下降 X%」句式**——确定性核验器对变动方向与数值做机器复算，自然语言方向词极易触发误报违规。任务书无指标表时，变动表述必须与引用的资料原文逐字一致。
- **不编造**：只使用任务书注入的数据与资料原文；快照页原文之外的信息不得作为事实陈述；无法支撑的判断改为中性描述。
- **派生值**：需要计算才得到的值，必须标注「基于 [C-k] 计算」并给出算式或依据，结果与引用材料一致。

## 5. 引用标注法

- 每个数据/事实陈述恰好标注一条 `[C-n]`（n 为任务书引用清单编号）。
- 一句话综合多个来源时，标注所引用的每条编号。
- 引用不可复用于无材料支撑的定性判断；定性判断不加引用标注，但不得与引用材料矛盾。

## 6. 续写响应（缺节/截断）

收到「上一轮输出不完整，缺少章节：…」时：

1. 在同一会话内按任务书补写缺失章节，已产出的节不要重写、不要复述；
2. 只输出缺失章节的块，输出协议不变；
3. 若缺失节依赖已产出的结论，可在表述上衔接，但不得改动已产出内容。

## 7. 修订响应（核验违规反思）

收到违规清单（数值核验/引用核验各一组 `[规则] 目标：详情`）时：

1. **定位**：按违规详情定位受影响的正文陈述（违规目标通常是 claim 编号或页码）；
2. **归因反思**：区分三类原因——①引用标注错/漏（改标注）；②事实表述与资料原文不一致（改为原文表述与 §4 句式）；③编造或派生未标依据（删改或补标注）；
3. **最小修订**：只修订受影响的章节；未修订的章节不要输出；
4. **输出协议**：仅输出被修订章节的块，块首行只写 `[S-n]`，正文从下一行开始，事实陈述标注 `[C-n]`；
5. 若某违规无法在遵守上文纪律的前提下消除，宁可改写为中性表述（去掉方向词与数值复述），也不要保留会被核验判负的陈述。

## 8. 交付自检清单

成稿输出前自查（不通过则先自纠再输出）：

- [ ] 章节清单内每节均有且仅有一个 `[S-n]` 块，且全部在最终答复中完整输出（方括号内无空格）；
- [ ] 每个数据/事实陈述有 `[C-n]` 标注；派生值有算式或依据；
- [ ] 值与单位与任务书/资料原文逐字一致；变动句式合规（§4）；
- [ ] 无快照页之外的事实性数据；
- [ ] 相邻节无同一材料的重复展开；
- [ ] 无开场白、无收尾总结、无对任务书本身的复述。
