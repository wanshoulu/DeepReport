# 深度联网调研方法（deep-search）

> 适用于通用域（`report_type != annual_report`）主题任务的**深度调研 agent（deep-search）**。
> 本文件是联网调研方法与流程的事实源；与 `general-report` 技能配套使用。
> 年报域默认使用冻结快照，**不触发**本方法（见 §1 门控）。

## 1. 职责定位与门控

- **deep-search agent 负责的事**：多轮联网调研——LLM 规划查询、评估资料充分性、改写再搜。
- **编排器（查数工位）负责的事**：判定是否触发（仅通用域且带 `subject_hint`）、组装主题、解析落盘结果、重算引用池。
- **框架提供的事**：会话记忆（同一 sessionId 跨轮可见已收集要点）、工具调用（web_search / web_fetch / snapshot_commit）。
- **门控铁律**：年报域（`annual_report`）禁止联网深搜，保持冻结快照纪律；通用域主题任务才启用。

## 2. 执行流程（与运行时 `deepSearch()` 实现一一对应）

1. **查询规划**：每轮由 LLM 规划 2 个互补查询（公司概况/主营业务/经营财务数据/客户与市场/风险），避免与已收集资料重复；LLM 不可达或返回不可解析时，降级为默认查询（主题 + "最新经营数据" / 主题 + "公司分析"），并在轮次记录中如实标注 `plan_source`。
2. **搜索与选链**：逐查询调用 `web_search` 聚合结果（标题 + 链接）；跨轮 URL 去重，已抓取过的不重复处理。
3. **抓取**：对选定链接调用 `web_fetch` 取正文；单条失败如实记录，不中断其余抓取。
4. **落盘注册（纪律门）**：抓取产物**必须**经 `snapshot_commit` 落盘注册进 live 快照集（sha256 注册）后方可被引用核验（C1/C2）与数值核验（N3）接受——「抓得到」与「可引用」之间有纪律门。
5. **信源权威分级**：落盘时按来源域名标注 `authority`——政府/交易所/监管站（gov.cn、sse.com.cn、szse.cn、cninfo.com.cn 等）为 `PRIMARY_OFFICIAL`；教育/机构/研究站（edu/org/cnki/research 等）为 `SECONDARY_INSTITUTIONAL`；无法判定的聚合源一律 `TERTIARY_AGGREGATED`（不虚报一手信源）。
6. **充分性评估**：每轮结束由 LLM 评估资料是否充分（严格 JSON 判定 `{"sufficient": bool}`；解析失败按「不充分」处理，不提前收束）。
7. **轮次上限**：最多 **3 轮**；评估充分则提前收束并记录 `stopped_reason`。

## 3. 失败语义（fail-open）

调研是**增强不是门禁**：LLM 不可达、搜索无结果、抓取失败都只记录原因（`error` / `rounds[]` 内逐轮明细），绝不阻断流水线。落盘 0 份时如实报告「无新增可落盘信源」。

## 4. 已知限制（如实声明）

- 上游搜索/抓取质量取决于 `web_search`/`web_fetch` 工具实现；本方法不保证结果完备性。
- 聚合源内容可能有噪声；引用时遵循 `general-report` 技能的引用纪律，权威级不足时正文须降级表述。
- 本方法不适用于年报域；年报域的资料纪律见 `annual-report` 技能。
